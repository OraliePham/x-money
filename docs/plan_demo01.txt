I. TỔNG QUAN DỰ ÁN
================================================================================

Mục tiêu: Xây dựng hệ thống quản lý nhiều profile trình duyệt độc lập với khả 
năng chống phát hiện bot tối đa, lưu trữ đầy đủ dữ liệu như Appdata thật.

Yêu cầu cốt lõi:
1. Mỗi profile có thư mục user_data riêng biệt (lưu cookies, cache, localStorage)
2. Tự động sinh cấu hình fingerprint ngẫu nhiên nhưng thực tế
3. Tích hợp các kỹ thuật anti-detection mạnh nhất
4. Hỗ trợ chạy đồng thời nhiều profile
5. Có khả năng export/import profile để backup

================================================================================
⚠️ KHÔNG sử dụng headless mode - 95% bot bị phát hiện qua headless

6.2. Lưu ý về performance:
================================================================================
⚠️ Mỗi profile tiêu tốn 200-400MB RAM
⚠️ Chạy 10 profile cần ít nhất 8GB RAM
⚠️ CPU usage tăng đáng kể khi nhiều profile cùng tải trang
⚠️ Nên giới hạn concurrent profiles (5-10 tùy cấu hình máy)

⚠️ Backup profile quan trọng thường xuyên

VII. CÁC RỦI RO VÀ GIẢI PHÁP
================================================================================

Rủi ro 1: Bị phát hiện dù đã áp dụng các kỹ thuật
------------------------------------------------
Nguyên nhân: Các trang web cập nhật phương thức phát hiện mới
Giải pháp: 
- Cập nhật stealth script thường xuyên
- Theo dõi các repo anti-detection (puppeteer-extra-stealth)
- Test định kỳ trên các trang detection

Rủi ro 2: Memory leak khi chạy nhiều profile
------------------------------------------------
Nguyên nhân: Không đóng context đúng cách
Giải pháp:
- Luôn gọi await context.close() sau khi dùng xong
- Dùng weakmap để theo dõi active contexts
- Set timeout tự động đóng profile không hoạt động

Rủi ro 3: Profile bị corrupt không load được
------------------------------------------------
Nguyên nhân: Tắt browser đột ngột hoặc lỗi disk
Giải pháp:
- Tự động backup profile mỗi ngày
- Implement recovery mechanism
- Log chi tiết lỗi để debug

Rủi ro 4: Bị rate limit bởi target website
------------------------------------------------
Nguyên nhân: Quá nhiều request từ cùng IP
Giải pháp:
- Dùng proxy pool xoay vòng
- Random delay giữa các request
- Implement exponential backoff khi bị block
